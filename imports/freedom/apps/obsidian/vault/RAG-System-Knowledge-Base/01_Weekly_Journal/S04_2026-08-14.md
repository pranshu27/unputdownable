## Session Close Addendum - 2026-08-14 (LLM Usage + Low-Score Tuning)

### Problem Observed
- Some smart-retrieval requests refused too aggressively even when friendly evidence existed.
- Query class like "give me all sql qualifiers" returned low hybrid scores and weak answer quality.

### Fixes Applied
- `src/rag_system/api/app.py`
  - Added retrieval fallback chain improvements:
    - retry original query when planner rewrite misses,
    - try anchor technical terms (`*_Id`, `wf_*`, `.XML`) before broad combined terms,
    - retry non-planner retrieval when smart results are low-confidence.
  - Added mode-aware scoring helper and thresholds:
    - vector/hybrid default threshold calibrated to `0.02` (env-overridable),
    - bm25 threshold remains separate.
  - Added explicit refusal messaging for low-confidence candidates.
  - Added SQL-qualifier intent steering:
    - detect `sql qualifier` / `QUALIFY` / `sql override` intent,
    - force lexical retrieval preference (`bm25`) and `TRANSFORMATION` focus,
    - enrich rewritten query with `QUALIFY SQL_OVERRIDE` tokens.

### Validation Snapshot
- Query: `Explain InteractionEvent_Id with cited evidence`
  - Result after fixes: `refused=false`, `llm_used=true`, evidence returned.
- Query: `QUALIFY SQL override` (bm25 probe)
  - Top hits now include `SQ_SQL_Override_*` transformations with much stronger lexical scores (~`0.33`).

### Outcome
- Main blocker resolved: valid evidence-backed requests now reach LLM generation reliably.
- SQL qualifier intent now routes to the retrieval mode that matches corpus signal quality.
